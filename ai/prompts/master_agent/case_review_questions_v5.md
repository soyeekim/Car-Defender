{{asked_fields}}

추론 순서 (reasoning에 그대로 적는다):
1. 가장 유사한 사례(usable_as_primary_reference)의 결정비율이 어떤 사실·수정요소로 정해졌는지 정리한다.
2. 그 사실·수정요소가 현재 사건에서 CONFIRMED 인지, 다르게 확인되었는지, 미확인인지 하나씩 대조한다.
   위 "이미 확인된 사실"과 CASE_STATE 의 status 를 그대로 따른다. CONFIRMED 인 항목을 미확인이라고 쓰지 않는다.
   사례의 수정요소가 현재 사건에서는 반대로 확인됐으면(예: 사례는 실선, 이 사건은 점선 CONFIRMED) "적용되지 않을 것"이라고 정리한다.
3. 미확인 항목을 두 갈래로 나눈다.
   (A) 영상 재분석으로 확인 가능 — 화면에 찍히는 사실(노면 실선/점선, 정지선, 블랙박스 차량 방향 신호등 색, 차로 위치,
       화면 안 상대 차량의 방향지시등, 제동·감속, 충돌 부위, 양 차량이 화면에 있을 때의 진입 순서) → video_recheck_targets
       단, status 가 UNKNOWN 인 항목만. 영상 분석이 "화각 밖/사각지대/보이지 않음"이라고 명시한 것은 (B)다.
   (B) 영상에 찍힐 수 없어 사용자만 아는 것(영상 시작 전 상황, 영상 분석이 "화각 밖/보이지 않음"이라고 명시한 것, 영상 밖 별도 충돌) → 질문 후보
   이미 재분석한 쟁점이 그래도 미확인이면 (B)로 보내도 된다.
4. (B) 중 답에 따라 기준값(결정비율)에서 벗어날지가 결정되는 것 하나를 질문으로 선택한다.
5. 더 확인할 것이 없으면 questions와 video_recheck_targets를 빈 배열로 두고 reasoning에 이유를 적는다.

금지:
- 화면에 찍히는 사실을 사용자에게 묻는 것 (→ 재분석 요청)
- 사용자의 주관적 과실 판단("잘못", "무리하게", "생각하시나요")을 묻는 것
- 영상에서 이미 VIDEO_CONFIRMED로 확인된 사실, 이미 물어본 항목을 다시 묻는 것 (이름만 바꿔 다시 묻는 것 포함)
- 과실비율과 무관한 정보(사고 일시, 장소명, 보험사 정보 등)를 묻는 것 — 문서 작성 시 따로 확인한다
- 사용자가 "모른다"고 답한 항목을 다시 묻는 것
- 한 번에 두 개 이상 묻는 것 (최대 {{max_questions}}개)
- 아래 출력 예시의 문장을 그대로 베끼는 것. 예시는 형식만 보여 준다. 사례 번호·사실·비율은 반드시 이 사건의 입력에서 가져온다.

작성 규칙:
- field: Case State 슬롯 경로(예: other_vehicle.turn_signal, ego_vehicle.entered_first, road.lane_marking)를 쓴다.
  상대 차량은 other_vehicle.*, 블랙박스 차량은 ego_vehicle.* 이다 (vehicles.vehicle_2.* 같은 영상 스키마 이름을 쓰지 않는다).
  맞는 슬롯이 없으면 `review.<snake_case>`로 네가 이름을 만든다.
- question: 한 문장, 해요체(~인가요?/~셨나요?), 선택지를 제시할 수 있으면 제시.
- why: 이 답이 어떤 수정요소(예: "실선구간 진로변경 +10")의 적용 여부를 결정하는지 한 문장. 사용자에게 그대로 보여주므로 해요체로 쉽게 쓴다.
- summary: 심의사례 대비 현재 사건에서 확인된 것과 아직 확인되지 않은 쟁점을 해요체 1~2문장으로. 확인된 사실을 미확인이라고 쓰지 않는다.

    "현재 사건: <해당 사실>은 <CONFIRMED/다르게 확인/미확인>, <다른 사실>은 <…>",
