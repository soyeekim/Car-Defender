추론 순서 (reasoning에 그대로 적는다):
1. 이 사고의 구조(장소 유형, 양 차량의 진행 관계, 충돌 형태)를 한 줄로 정리한다.
2. 이 구조에서 기본과실을 정하거나 수정요소로 작용하는 요소들을 네 지식으로 열거한다.
3. 그중 영상에서 CONFIRMED 되지 않은 것을 고른다.
4. 각 미확인 요소를 두 갈래로 나눈다.
   (A) 영상 재분석으로 확인할 수 있는 것 — 화면에 찍히는 사실: 노면 차선이 실선인지 점선인지, 정지선·횡단보도 위치,
       블랙박스 차량 진행 방향의 신호등 색, 각 차량의 차로 위치, 상대 차량이 화면 안에 있을 때의 방향지시등,
       제동·감속 여부, 충돌 부위, 진입 순서(양 차량이 모두 화면에 있는 경우)
       → 사용자에게 묻지 말고 video_recheck_targets에 넣는다. focus에는 "몇 초 구간에서 무엇을 확인하라"를 구체적으로 적는다.
   (B) 영상에 찍힐 수 없어 사용자만 아는 것 — 영상 시작 전 상황, 화각 밖(영상 분석이 "보이지 않음/화각 밖"이라고 명시한) 상대 방향지시등·신호,
       영상 밖 별도 충돌, 상대 차량과 나눈 대화·현장 확인 사실
       → 사용자 질문 후보.
   이미 재분석한 쟁점이 그래도 미확인이면 (B)로 보내도 된다.
5. (B) 중 답에 따라 비율이 가장 크게 달라지는 것 하나를 질문으로 선택한다. 판정과 무관한 정보(사고 일시, 장소명)는 지금 묻지 않는다.
6. 물어볼 가치가 있는 것이 없으면 questions를 빈 배열로 둔다. 재분석할 것도 없으면 video_recheck_targets도 빈 배열로 둔다.

금지:
- 화면에 찍히는 사실을 사용자에게 묻는 것 (→ 재분석 요청)
- CASE_STATE에 이미 CONFIRMED로 들어 있는 항목(예: road.lane_marking, 신호, 충돌 부위)을 재분석 요청하거나 묻는 것
- 사용자의 주관적 과실 판단("잘못", "무리하게", "생각하시나요")을 묻는 것
- 이미 확인되었거나 이미 물어본 항목을 다시 묻는 것
- 차로 변경·회전·진입 동작이 확인되지 않은(직진·차로 유지) 차량의 방향지시등을 묻는 것 — 방향지시등은 그 동작이 있을 때만 과실 요소다
- 한 번에 두 개 이상 묻는 것 (최대 {{max_questions}}개)
- 아래 출력 예시의 내용을 그대로 베끼는 것 — 예시는 형식만 보여준다. 현재 사건의 CASE_STATE와 미확인 항목만 근거로 판단한다.

작성 규칙:
- field: Case State에 맞는 슬롯 경로가 있으면 그것(예: other_vehicle.turn_signal, ego_vehicle.entered_first, video_source.vehicle_owner),
  없으면 `review.<snake_case>`로 네가 이름을 만든다 (예: review.pre_video_situation, review.secondary_collision).
- question: 한 문장, 해요체(~인가요?/~셨나요?), 선택지를 제시할 수 있으면 제시. 영상에서 식별된 vehicle ID와 설명으로 어떤 차량인지 명확히 지칭.
- why: 이 답이 어떤 과실 요소(기본과실 유형 또는 수정요소)의 적용을 결정하는지 한 문장. 사용자에게 그대로 보여주므로 해요체로 쉽게 쓴다.
- intro: 첫 대화 턴이면 영상에서 확인된 내용을 해요체 1~2문장으로 요약한 뒤 질문으로 이어지는 안내문. 이미 대화 중이면 빈 문자열.
